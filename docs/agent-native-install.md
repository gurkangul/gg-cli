# Agent-native install

gg is an alpha CLI that agents call as a subprocess. It does not expose a
REST API, MCP server, hosted service, or daemon.

Use this page to install the same `gg` protocol into Codex, Claude Code,
Cursor, or a plain shell workflow.

## 1. Install the CLI

```sh
go install github.com/gurkangul/gg-cli/cmd/gg@latest
```

Then initialize each project:

```sh
cd /path/to/project
gg init
gg doctor
gg doctor --install-agent-hooks
```

`gg init` writes the project protocol to `AGENTS.md`. The hook installer adds
agent-specific rule files where gg knows how to do that safely.

## 2. Codex

Recommended project-local path: `AGENTS.md`, generated by `gg init`.

Optional global reminder in `~/.codex/instructions.md`:

```markdown
When a project contains AGENTS.md with gg rules:
- Start with `export GG_AGENT=codex` and `gg status`.
- Before proposing work, run `gg search "<topic>" --compact`.
- Use `gg context "<topic>" --compact` before implementation.
- Read messages with `gg inbox --role "$GG_ROLE" --since-cursor`.
- Create/claim tasks with `gg task ...` and broadcast substantial work with
  `gg tell all "...status..." --from <role> --audience agents`.
- Before editing source files, run `gg impact <file> --compact`.
- Record decisions/rejections with `gg record`.
```

## 3. Claude Code

Recommended project-local path: `CLAUDE.md` plus `AGENTS.md`.

Run:

```sh
gg doctor --install-agent-hooks
```

Claude should start each project session by reading `CLAUDE.md`/`AGENTS.md`,
setting `GG_AGENT` to the runtime identity, running `gg status`, and summarizing open
tasks, unread inbox, and recent decisions.

## 4. Cursor

Recommended project-local path: `.cursor/rules/gg.mdc`.

Run:

```sh
gg doctor --install-agent-hooks
```

Cursor rules should require:

```sh
export GG_AGENT=cursor
gg status
gg inbox --role "$GG_ROLE" --since-cursor
```

Before code changes, Cursor should run `gg search`, `gg context`, and
`gg impact` the same way Codex and Claude Code do.

## 5. Manual shell workflow

For agents or editors without a rule-file integration, start the terminal
session like this:

```sh
export GG_AGENT=manual
export GG_ROLE=developer
gg status
gg inbox --role "$GG_ROLE" --since-cursor
```

Use this loop:

```sh
gg search "topic" --compact
gg context "topic" --compact
gg task get TASK-123
gg impact path/to/file.go --compact
gg tell all "TASK-123 picked up" --from "$GG_ROLE" --audience agents
```

When implementation is ready, follow the repository's verifier rules. If
ready-for-live is enabled, the implementer sets:

```sh
gg task ready-for-live TASK-123 "verification plan" --from developer
```

Then a separate verifier closes:

```sh
gg task done TASK-123 "verified summary" --verifier reviewer
```

## 6. Role and runtime routing

When a project has multiple runtimes, record the human's assignment in
`.gg/config.yaml` instead of relying on memory:

```sh
gg config set roles.master.command "codex --model gpt-5.5"
gg config set developer.command "gsd --model openai-codex/gpt-5.3-codex"
gg config set roles.reviewer.command "codex --model gpt-5.3-codex"
```

For quota or runtime fallback, add named profiles. Lower priority wins; a
`health_command` must return exit 0 when the runtime can take work.

```sh
gg config set runtime_profiles.gsd-dev.role developer
gg config set runtime_profiles.gsd-dev.priority 10
gg config set runtime_profiles.gsd-dev.command "gsd --model openai-codex/gpt-5.3-codex"
gg config set runtime_profiles.codex-dev.role developer
gg config set runtime_profiles.codex-dev.priority 20
gg config set runtime_profiles.codex-dev.command "codex --model gpt-5.3-codex"
```

`gg spawn worker --role reviewer --task TASK-123` resolves the reviewer
runtime from `runtime_profiles` first, then falls back to
`roles.reviewer.command`. `gg status` prints the active role/profile routing.
`gg system sync` propagates managed protocol artifacts, but it does not
overwrite per-project role/profile assignments; run the `gg config set`
commands in each project that needs different agents.

## Skill bundle

For agents that support skill directories, copy the bundled skill template:

```sh
mkdir -p ~/.agents/skills
mkdir -p ~/.agents/skills/gg-cli
cp /path/to/gg-cli/docs/agent-bundles/gg-cli-skill.md \
  ~/.agents/skills/gg-cli/SKILL.md
```

The skill is intentionally only instructions. It does not create a server and
does not bypass `AGENTS.md`; project-local gg rules remain authoritative.
